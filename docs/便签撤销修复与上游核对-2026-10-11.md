## 已修问题与行为

| 问题 | 根因与改动 | 验证范围 |
| --- | --- | --- |
| 未改便签破坏后无法与原物品堆叠 | `preRemove` 曾无条件写入空正文、标题、作者和签名字段。现在未改变内容时保留源物品元数据；已保存的控制器文本仍优先，确实编辑后才回写。 | 空白、文本、签名、BookMeta-only 便签的控制器回归；真实 CE/Bukkit 物品相似性探针。 |
| 放置便签同时打开原版编辑器 | 书与笔载体的客户端使用流程会打开编辑器；服务端取消事件不足以可靠阻止。未签名便签改用纸载体，保留模型和 16 堆叠。 | 内容包配置回归；Purpur 26.2 真实物品载体、堆叠上限和迁移检查。 |
| 放置后编辑不能工作 | 原 `OpenBook` 数据包打开的是阅读界面，无法充当书与笔编辑界面。删除临时换书和发包编辑流程，改用 Paper `AsyncChatEvent` 私密输入，回玩家/家具所属调度执行。 | 输入解析、255/16 Unicode 码点上限和取消测试；玩家点击流程仍待 T06/T07。 |
| 旧便签迁移 | 玩家加入、关闭库存时迁移旧书与笔；切换槽位仅迁移目标槽，交换手只检查两件物品。保留模型和其它自定义数据，捕获旧书第一页正文，移除旧 writable-book 组件；仅清除已知字段构成的空便签树。 | 旧空白便签与新物品可堆叠；旧书页转为 note 数据，不保留书编辑组件；未知额外字段不会按空便签删除。 |
| 便签复制 | 换纸载体后不能继续依靠原版 writable-book 克隆配方。注册 1～8 张空白便签的 Bukkit 无序配方，保留签名源，只消耗空白便签，原件/复制件推进 generation。 | 八条配方实际注册；库存容量边界单测。支持普通左右点击和 Shift；数字键、丢弃等取出方式目前不执行复制。 |
| 捕蟹笼不认含水 CE 方块 | 原版承载方块不一定体现 CE 逻辑水状态。先判断原版水/含水，必要时读取已加载 CE 状态的 `waterlogged` 属性。 | 原版水、水生植物、干燥/含水逻辑状态及缺失状态测试；真实捕蟹笼需 T18。 |
| undo 索引 -1 | 查询历史时压缩了正在撤销的空记录，破坏后续分片的固定索引。查询只移除整批全空记录，完成撤销后才压缩内部列表。 | 旧实现复现失败；6874 条记录、每 16 条穿插历史查询的回归通过。 |

放置后的编辑方式是右键未签名便签，发送正文保存；文字中的 `\n` 转为换行。重新右键后发送 `!sign 标题` 对当前正文签名，`!clear` 清空，`!cancel` 放弃。退出、换物品、传送等会取消会话；失去距离/区域/保护授权不应用旧编辑。签名便签右键只读。聊天事件取消广播，但仍应和服务器实际聊天插件联合验收。

**更正历史结论**：之前把“发送打开书本包”当成放置后可编辑的保证，证据不足。现在代码采用独立输入流程；19 项服务端数据断言也不等于客户端点击已验收。仅带 BookMeta、没有 note 树的 CAB 旧物品已加入读取回退；并不承诺任意外部物品都转为 CAB 家具。

捕蟹笼仍使用原有 20 tick 环境缓存，不强制加载区块、不增加异步世界读取或常驻轮询。便签迁移没有逐 tick 扫库存，非旧书载体直接返回。FD 发行包业务仅注释整理，撤销修复属于 debug 构建。
